# 06 — 하란이 3D가 됐다, 그리고 2D는 테스트 도구로 남는다

> 2026-08-03 · 작성: Claude (개발 세션 AI) · 방향 결정: Hakhyun

"비주얼 환경으로 3D 화면 추가해줘. 다만 지금 것도 테스트용으로 유지해줘."

## 클라이언트는 뷰일 뿐이다 — 구조가 또 밥값을 했다

서버 권위 + 룸 계약 구조의 부수 효과: **클라이언트를 몇 개 붙이든 서버는 모른다.** 그래서 3D 클라이언트 추가는 서버 코드 수정 없이 새 패키지 하나로 끝났다.

- **`client3d` (고비주얼)** — Three.js 쿼터뷰. 캡슐 플레이어, 절차 생성 나무·바위·약초(로우폴리), 그림자, 클릭 이동(레이캐스트), 자원 클릭 채집, 카메라 추적 + 휠 줌. 프로덕션 루트(`/`)에 서빙.
- **`client` (테스트)** — 기존 2D Phaser 도형 렌더. 가볍고, 상태가 한눈에 보이고, 검증에 유리하다. 프로덕션 `/test`에 서빙.

`npm run dev` 한 번에 서버(7777) + 2D(5173) + 3D(5174)가 뜬다. 두 클라이언트는 같은 세계다 — 3D에서 걷는 사람이 2D 화면에도 사각형으로 걷는다.

## 검증 — AI 플레이어가 3D 신입을 맞이했다

일지 05의 MCP 도구를 이번엔 검증 도구로 썼다. 브라우저에서 사람 캐릭터(torin3d)가 3D로 입장한 뒤:

1. 내(Claude)가 MCP로 입장 → 3D 화면 채팅창에 "Claude 님이 입장했습니다" — 상태 바인딩 확인
2. 3D 화면 클릭 → torin3d가 서버 좌표 (640,480)→(640,281)로 이동 — 레이캐스트→서버 판정 확인
3. 화면의 약초 클릭 → 이동→채집→"획득 +1 (herb)"→가방 갱신 — 전체 루프 확인

사람 클라이언트의 E2E 테스트를 AI 플레이어가 상대해 주는 그림이 됐다. 봇이 시민인 게임의 개발 방식은 이렇게 된다.

## 결정 기록 D9 — 그리고 D3의 부분 재개봉

픽셀아트로 간다던 D3는 3D 전환으로 부분 재개봉됐다. 에셋 방향은 절차 생성(현재) → 로우폴리 CC0(Kenney/Quaternius 계열)로 수정. 재개봉 원칙(일지 04)을 세워둔 덕에 이번엔 기록 한 줄로 끝났다.

덤으로 발견한 것: dev에서 2D(5173)와 3D(5174)는 다른 origin이라 로그인 토큰이 공유되지 않는다. 프로덕션(같은 origin의 `/`와 `/test`)에서는 문제없다 — 결과적으로 계정-토큰 설계가 origin 경계를 그대로 따라간다는 걸 확인했다.
