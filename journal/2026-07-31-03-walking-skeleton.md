# 03 — 걷는 뼈대: 첫 커밋에 PROTOCOL.md

> 2026-07-31 · 작성: Claude (개발 세션 AI) · 방향 결정: Hakhyun

기획을 일단락하고 Phase 1 코딩을 시작했다. 오늘 세운 수칙 두 개: **로컬에서 명령 하나로 전부 뜰 것, 나중에 클라우드로 옮기기 쉬울 것.**

## 첫 기술 결정 — Colyseus를 버리다

GDD엔 Colyseus를 쓴다고 적어뒀었다. 그런데 코딩을 시작하려는 시점에 원칙과 부딪혔다: Colyseus는 자체 바이너리 스키마로 상태를 동기화한다. 그 프로토콜은 "문서만 읽고 봇을 만들 수 있어야 한다"(P6)와 양립하지 않는다 — 봇을 만들려면 결국 colyseus.js 라이브러리가 필요해지고, 그 순간 "같은 문"이 아니라 "전용 문"이 생긴다.

그래서 **순수 JSON over WebSocket 자체 프로토콜**로 갔다. 이 게임은 클릭 이동에 쿨다운 기반이라 고빈도 동기화가 필요 없다. 동접 수십 명 × 100ms 틱의 JSON은 아무 부담이 아니다. 프레임워크 종속이 없으니 이식성 수칙에도 맞는다. 편의보다 원칙이 이긴 첫 사례로 기록해 둔다.

## PROTOCOL.md가 헌법이다

저장소 첫 커밋에 [PROTOCOL.md]가 들어갔다. 로그인, 이동, 채팅, 채집의 전체 메시지 규약 — 레이트 리밋(초당 20개, 봇도 사람도 동일)과 오류 코드까지. 문서 첫머리에 이렇게 썼다:

> 이 문서만 읽고 봇을 만들 수 있어야 한다. 문서와 서버가 어긋나면 그것은 버그다.

말로만 하면 거짓말이 되니까 테스트로 강제했다. 스모크 테스트는 **일부러 공유 타입을 임포트하지 않고** 문서에 적힌 JSON 리터럴을 그대로 보낸다. 레퍼런스 봇(`packages/bot`)도 마찬가지다. 문서가 낡으면 테스트가 깨진다.

## 오늘 움직인 것

모노레포 4패키지(protocol / server / client / bot), 명령 하나(`npm run dev`)로 서버+클라이언트 동시 기동.

- **서버**: 권위 시뮬레이션. 이동(160px/s, 100ms 틱), 채팅, T1 채집 노드 9개(나무·바위·약초), 인벤토리, 이름+토큰 계정, 파일 스토리지. 게임 로직(world.ts)은 네트워크를 모른다 — 시뮬과 전송의 분리가 나중에 스케일아웃의 생명줄이다.
- **클라이언트**: Vite + Phaser. 클릭 이동, 노드 클릭 → 접근 → 자동 채집, 채팅 HUD. 아직 도형 플레이스홀더다(픽셀아트는 다음).
- **봇**: PROTOCOL.md만 보고 작성한 채집 봇. 실서버에 붙여 보니 —

```
[bot] woodbot 입장 — haran (640, 480), 노드 9개
[bot] 목표: n_rock_4 (rock, 남은 5)
[bot] 획득: copper_ore ×1 — 가방: { copper_ore: 1 }
```

같은 시각 브라우저에서 사람 캐릭터가 봤다: "woodbot 님이 입장했습니다". **사람과 봇이 같은 서버에 같은 문으로 들어와 있다.** P6가 첫날부터 코드로 성립했다.

이식성 수칙은 6줄로 README에 박았다: 설정은 env로(기본값은 로컬), 주소 하드코딩 금지, 영속화는 Storage 인터페이스 뒤에만(지금은 JSON 파일 → 나중에 Postgres), 프로덕션은 단일 프로세스(서버가 클라이언트 정적 파일까지 서빙 — Docker 한 장으로 어디든), 판정은 전부 서버 권위.

## 오늘의 함정 — PORT는 누구의 것인가

프리뷰 러너가 `PORT=5173`을 주입하자 게임 서버가 그걸 읽고 5173에 바인딩했다. Windows에서는 `0.0.0.0:5173`(게임 서버)과 `127.0.0.1:5173`(Vite)이 **에러 없이 공존**해서, 모든 게 떠 있는데 접속만 안 되는 상태가 됐다. `PORT` env 관례는 클라우드 배포(Heroku, Cloud Run이 PORT를 주입한다)를 위해 유지하되, dev 스크립트에서만 `cross-env PORT=7777`로 고정하는 걸로 정리. 이식성 수칙 1번이 첫날부터 밥값을 했다.

## 검증 상태
